# External Repository Intake V2 — 2026-09-20

Status: **research intake only**. This is an additive successor to V1 and does not rewrite the first eight observations.

The second generation contains ten newly supplied repositories. Exact source head, license state, lifecycle, evidence blobs, destination, and non-effects are recorded before any pattern can be considered for Vera-owned work.

## Highest-value additions

### Hermes Agent

Hermes is a strong design reference for agent-state separation. The useful mechanisms are explicit backend identity/failure scopes, subagent lifecycle objects instead of leaked live agent instances, and separation between memory/session-search state, user modeling, skills, and runtime execution. These are architecture patterns only. Hermes memory or identity never becomes Vera autobiographical memory, selfhood, authority, or standing preference automatically.

### OpenHands

OpenHands is useful for the Exodus/BT2 idea that an execution terminal is replaceable while durable worker/task identity lives elsewhere. Its backend identity and connection/config revision patterns are relevant to stale-route prevention and local/remote/cloud backend switching. That does not make OpenHands a Vera runtime dependency.

### ChatGPT Route Inspector

This unofficial extension is useful only as an **evidence-model reference**. Its strongest ideas are proposition separation: requested model versus observed response route, live-request versus session-reload evidence, revision-scoped capture contexts, and preserving conflicting observations rather than inventing certainty.

The repository has no detected license and is not an OpenAI authority. No source copying is allowed by this intake. Any Vera implementation must be clean-room and must use Vera/OpenAI-authoritative provider evidence where available.

### Langflow / LangChain

These are comparison baselines for workflow and agent orchestration. They are not defaults. A future adoption proposal must demonstrate a concrete capability or maintenance benefit that existing Project Runner/BT2 mechanisms do not already provide.

## Adversarial and cyber sources

`ChatGPT-JailBreak` and `hackGPT` are **DATA_NOT_INSTRUCTION**. Retrieved personas, jailbreaks, issue descriptions, malware/security corpora, CVE material, and offensive examples cannot grant tool authority or effect permission.

`hackGPT` is especially useful as a negative-control example: untrusted issue text can be fed to a model and model output can be posted back to JIRA. Our governed lesson is the opposite: model analysis, issue content, external corpora, and action authority are separate propositions.

No exploit generation, malware execution, jailbreak execution, blocklist installation, training, or external mutation follows from this intake.
