# External Repository Intake — 2026-09-20

Status: **research intake only**. These repositories are evidence/pattern sources, not dependencies, control owners, installed Project sources, Vera memory, or runtime state.

The intake binds each observation to an exact repository head and records license/lifecycle before reuse. Discovery never promotes a source automatically.

## Highest-value patterns

### Khazix Skills
`leader` formalizes a useful separation between goal, harness, evidence, forbidden shortcuts, resumable progress, and independent acceptance. `neat-freak` adds a closeout matrix across code, runtime, docs, rules, memory, and workspace with explicit states rather than a fake single “done”.

VCP already separates source/install/runtime/effect; the useful extension is to make task packets and closeouts prove every relevant truth surface explicitly.

### Nylon / Aether
Both are network research, not VCP implementation targets. Nylon is especially relevant to VeraMesh because it treats routing as a self-healing distributed system with convergence after failure and no central coordinator. Aether adds a strong operational rule: a route is not good because a handshake succeeds; it is good only after actual data-plane traffic succeeds.

Any implementation belongs first to VeraMesh research custody. VCP may consume resulting qualification/control evidence later.

### DNSCrypt server Docker
The operational pattern is valuable for VCP recovery: durable identity/keys live outside the replaceable runtime, replacement starts only after durable state is verified, and the predecessor is retained until the successor is confirmed running.

### NEO
NEO contributes local-first custody and reversible editing ideas: plain files, “Darlings” instead of destructive deletion, unresolved placeholders, SHA-256 export receipts, continuous autosave, and rotating backups. These are recovery/creative-workflow patterns, not an application dependency.
